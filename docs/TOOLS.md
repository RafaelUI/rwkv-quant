## QLoRA поверх `.rwkvq` в rwkv-metal (19-20.07, актуально)

Всё бит-в-бит сверено с `rwkv_quant.formats.reader`. MLX-порт sb6/asym
dequant (`rwkv_metal/lora/rwkvq_linear.py`, `rwkvq_kernel.py`) — 0
расхождений на реальных тензорах. Финальный combine ОБЯЗАТЕЛЬНО в
float32: `GwQuantLinear._dequant_w()` держит математику в half и даёт
~18% расхождений на 1 бит bf16-мантиссы.

| путь | шаг (steady) | mx_peak | maxrss |
|---|---|---|---|
| stock QLoRA (nn.quantize 6bit) | 0.80-0.89 с | 3.02 ГБ | ~6.9 ГБ |
| rwkvq, наивный MLX-порт | 3.4-3.6 с | 4.39 ГБ | 6.6-7.0 ГБ |
| rwkvq, fused-кернель | 1.2-1.3 с | 3.65 ГБ | 3.64 ГБ |
| rwkvq, native quantized_matmul | 0.7-0.8 с | 4.59 ГБ | 4.36 ГБ |
| rwkvq, гибрид | 0.8-0.9 с | 4.19 ГБ | 4.62 ГБ |

Незакрытое: `emb.weight` не квантуется ни в одном пути (нужен
indexed-gather); native/hybrid проверены только для bits=6; качество
после сотен шагов не мерено; COMPRESSION как QLoRA-база не пробован.

  своп не растёт. `--gate <ckpt>` — обязательная проверка, что
  предквантование бит-в-бит тождественно кванту на лету; гонять её после
  ЛЮБОЙ правки forward в `rwkv7_ref.py`, иначе замер тихо разъедется с
  тем, что реально считает модель.
  JSON: `/tmp/sym_composite_1p5b.json`, `/tmp/sym_composite_2p9b_full.json`.
- `tests/eval_2p9b_one.py <config>` + `tests/eval_2p9b_report.py` —
  2.9B, ПО КОНФИГУ НА ПРОЦЕСС (законы 11 и 13). Конфиги: `bf16`,
  `reduction`, `reduction_small`, `reduction_fix`, `compression`,
  `compression_fix`. bf16-ветка не идёт через `quantize_tensor` (там
  `.clone()` = 5.9 ГБ анонимной памяти поверх уже отображённого файла).
